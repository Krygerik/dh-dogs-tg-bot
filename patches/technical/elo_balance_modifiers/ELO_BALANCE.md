# Elo balance: ладдер (API) и ручные множители (окружение)

## Режимы

1. **Ладдер (по умолчанию)** — ни одна из переменных множителей ниже не задана. Скрипт вызывает `POST /stats/elo-balance`, коэффициенты считает `computeEloBalanceModifiers` в боте.
2. **Ручной режим** — задана **хотя бы одна** переменная окружения с множителем. Запрос к API балансировщика **не выполняется**; применяются **только** те моды, для которых в окружении передано число (остальные остаются нейтральными ×1). В метаданных сессии (`elo_balance_meta.balancerAppliedModifiers`) попадают **только** явно заданные моды.

Переменные общего поведения Frida (не множители): `DH_ELO_BALANCE_SOLO_TEST`, `DH_ELO_BALANCE_DEBUG`, `DH_ELO_BALANCE_INGAME_LOG`, `DH_ELO_BALANCE_DISABLE_FALLBACK` — как раньше.

## Перечень переменных окружения для множителей

| Переменная | Ключ в API / `modifiers` | Диапазон | Шаг |
|------------|--------------------------|----------|-----|
| `DH_ELO_PREDATOR_DAMAGE_MULT` | `predatordamage` | 0.25 … 3 | 0.25 |
| `DH_ELO_PREDATOR_HEALTH_MULT` | `predatorhealth` | 0.25 … 3 | 0.25 |
| `DH_ELO_PLAYER_MELEE_MULT` | `playermeleedamage` | 0.5 … 2 | 0.25 |
| `DH_ELO_PLAYER_RANGED_MULT` | `playerrangedamage` | 0.25 … 1 | 0.25 |

Значение приводится к сетке 0.25 на стороне `loader.py`; числа вне диапазона для соответствующего мода **игнорируются** (мод из этой переменной не активируется).

Пример (PowerShell): только дальнобой ×0.25, без API:

```powershell
$env:DH_ELO_PLAYER_RANGED_MULT = "0.25"
```

Пример двух модов без подсчёта рейтинга:

```powershell
$env:DH_ELO_PREDATOR_DAMAGE_MULT = "1.5"
$env:DH_ELO_PLAYER_MELEE_MULT = "1.25"
```

В лог Frida уходит строка вида `elo_balance mode=manual_env appliedKeys=...`, по каждому применённому моду — `source=manual_env`.

## Таблица «стоимости весов» и диапазоны (логика ладдера)

Суммарный вес **T** считается из разницы средних рейтингов команд: за каждые **5** пунктов `|avgCrew − avgThrall|` (по умолчанию, см. `ELO_RATING_DIFF_PER_WEIGHT_UNIT`) даётся **1** единица веса, с учётом капа и неклассического состава.

| Мод (ключ) | Стоимость одного шага сетки 0.25 (в единицах веса) | Участие в T | Диапазон множителя |
|------------|------------------------------------------------------|-------------|---------------------|
| `predatordamage` | **1** | случайный сплит `d+h=T` с `predatorhealth` | 0.25 … 3 |
| `predatorhealth` | **1** | тот же сплит | 0.25 … 3 |
| `playermeleedamage` | **1** | не в сплите d/h; формула от `diff`; один шаг по шкале — как у остальных по «цене» | 0.5 … 2 |
| `playerrangedamage` | **1** | не в сплите d/h; при `diff < 0` и **T ≥ 1** | 0.25 … 1 |

Константа `ELO_WEIGHT_PER_GRID_STEP` (= 1): одинаковая стоимость шага для всех модов.

Итоговый сплит хищников: `splitTotalWeightBetweenDamageAndHp` — случайное разбиение `T` на шаги урона и HP при **равной** цене шага (**d + h = T** при `w = 1`).

Подробнее см. `src/stats/balance-modifiers.ts`.

## Frida: ближний и дальний урон игроков

Один скрипт `player_weapon_damage_lib.js`: один хук `AdjustDamage`, сначала классификация лук/пистолет/мушкет → множитель `playerrangedamage` (`__DH_PLAYER_RANGED_DAMAGE_MULT`), иначе ближний бой → `playermeleedamage` (`__DH_PLAYER_MELEE_DAMAGE_MULT`). Два отдельных множителя не смешиваются на одном попадании.

## Frida: принудительное переопределение (только режим API)

В ручном режиме окружения приоритет у значений из `__DH_ELO_MANUAL_MODIFIERS`; глобалы `__DH_ELO_PLAYER_MELEE_FORCE` / `__DH_ELO_PLAYER_RANGED_FORCE` в этом режиме **не используются**. В режиме API они по-прежнему могут переопределить ответ балансировщика для ближнего/дальнего боя.
